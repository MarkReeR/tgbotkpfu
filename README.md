# Бот расписания ВТШ КФУ

Телеграм-бот, который показывает расписание пар по номеру группы. Данные берутся
напрямую из общедоступной Google-таблицы с расписанием, выбранная пользователем
группа запоминается в SQLite и переживает перезапуск бота.

Порт Python-версии (`MarkReeR/tgbotkpfu`) на Go.

## Как пользоваться

`/start` закрепляет в чате приветственное сообщение с кнопкой «Смена группы»
и показывает главное меню:

```
📅 Расписание
🏃 Физра
📝 Экзамены          (только если [exams] Show = true)
🔄 Смена группы
```

**Расписание** просит номер группы (например `8261160`), запоминает его и
дальше сразу открывает выбор периода:

```
Сегодня   Завтра   Вся неделя
      Главное меню
```

Карточка дня выглядит так: «<» и «>» листают дни, «☰» возвращает в главное меню.

```
📅 Четверг [в] · 27.08.2026
──────────────────────
09:40 - 11:10 · лекция
Информатика
УЛК-4, ауд. 235 · Якупова Г.А.

11:50 - 13:20 · практика
Иностранный язык
УЛК-4, ауд. 237 · Мустафина Л.Р.

          [<] [☰] [>]
```

За кнопкой **Вся неделя** — подменю с фильтрами:

```
Текущая неделя   Следующая неделя   Вся без фильтров
                     Назад
```

**Физра** — расписание для спецмед групп. Его нет в основном расписании ВУЗа
(обычно висит бумажкой в спорткомплексе), поэтому оно ведётся в отдельной
таблице, см. раздел ниже. Показывается целиком: студенты спецмеда ходят на
любое удобное занятие, поэтому выбирать там нечего.

**Экзамены** пока заглушка — данных нет. Кнопка скрыта по умолчанию и
включается на период сессии флагом `Show` в секции `[exams]` конфига.

Кроме номера группы (`8261160`) бот понимает её «человеческое» имя (`18.1-642`)
и однозначный кусок номера — если совпадений несколько, он покажет список и
попросит уточнить.

## Запуск в Docker

Образ собирается в GitHub Actions и публикуется в GHCR, поэтому серверу не нужен
ни Go, ни компиляция — только скачать готовые 22 МБ:

```bash
cp .env.example .env
```

Вписать в `.env` токен от [@BotFather](https://t.me/BotFather), затем:

```bash
docker compose up -d
```

Обновление до новой версии — две команды:

```bash
docker compose pull && docker compose up -d
```

Собрать образ локально из исходников (нужно ~1 ГБ RAM):

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

Логи:

```bash
docker compose logs -f
```

База с выбранными группами лежит в именованном томе `bot-data`, поэтому
пересборка и перезапуск её не теряют.

Контейнер работает не от root (uid 65532). Именованный том получает нужного
владельца автоматически, а вот если смонтировать папку с хоста
(`-v ./data:/app/data`), права надо выдать самому:

```bash
mkdir -p data && sudo chown -R 65532:65532 data
```

### CI/CD

| Workflow | Когда | Что делает |
| --- | --- | --- |
| `.github/workflows/ci.yml` | push и pull request | gofmt, `go vet`, тесты с `-race`, сборка без cgo; на PR ещё и проверка Dockerfile |
| `.github/workflows/release.yml` | push в `main` и теги `v*` | собирает образ и публикует в GHCR |

Теги образа: `latest` для `main`, `v1.2.3` для git-тегов и `sha-abc1234` для
любого коммита — на последний удобно откатываться.

Пакет в GHCR по умолчанию приватный. Чтобы сервер мог скачивать образ без
авторизации, после первой публикации сделайте его публичным: страница пакета →
Package settings → Change visibility → Public.

### Версия сборки

Версия вшивается в бинарник на этапе сборки и печатается первой строкой лога:

```bash
docker build --build-arg VERSION=v1.0.0 -t tgbotkpfu:v1.0.0 .
```

Без явного аргумента будет `dev`. CI подставляет короткий хеш коммита.

## Запуск без Docker

```bash
cp config.ini.example config.ini   # и вписать BotKey от @BotFather
go run ./cmd
```

Драйвер SQLite чистый на Go, поэтому ни cgo, ни gcc не нужны — собирается
одной командой на любой машине:

```bash
CGO_ENABLED=0 go build -o bot ./cmd
```

## Настройка

Настройки читаются из `config.ini`, и **любую можно переопределить переменной
окружения** — так и работает контейнер. Если все нужные переменные заданы,
файл `config.ini` вообще не обязателен.

| Переменная | Секция в config.ini | По умолчанию | Что это |
| --- | --- | --- | --- |
| `BOT_TOKEN` | `runArgs.BotKey` | — | Токен от @BotFather (обязательно) |
| `SPREADSHEET_ID` | `schedule.SpreadsheetId` | — | ID таблицы с расписанием (обязательно) |
| `SHEETS` | `schedule.Sheets` | — | Вкладки в виде `1 курс:0,2 курс:123` (обязательно) |
| `REFRESH_MINUTES` | `schedule.RefreshMinutes` | `15` | Как часто перекачивать таблицы |
| `PHYSED_SPREADSHEET_ID` | `physed.SpreadsheetId` | пусто | Таблица физры; пусто — раздел выключен |
| `PHYSED_GID` | `physed.Gid` | `0` | Вкладка с расписанием физры |
| `PHYSED_VENUE` | `physed.Venue` | пусто | Место занятий физрой |
| `EXAMS_SHOW` | `exams.Show` | `false` | Показывать кнопку «Экзамены» |
| `LOG_LEVEL` | `runArgs.LogLevel` | `INFO` | `DEBUG`, `INFO`, `WARN`, `ERROR` |
| `LOG_DIR` | `runArgs.LogDir` | `logs` | Куда писать файлы логов |
| `DATABASE_PATH` | `runArgs.DatabasePath` | `Database.db` | Файл SQLite |
| `TZ` | `runArgs.Timezone` | `Europe/Moscow` | Пояс для «сегодня» и «завтра» |
| `CONFIG_PATH` | — | `config.ini` | Путь к файлу конфига |

Токен нигде не логируется, `config.ini` и `.env` исключены из git и из образа.

## Структура

| Путь | Что делает |
| --- | --- |
| `cmd/main.go` | Точка входа: логи, БД, кэши расписания, graceful shutdown |
| `Config/` | Чтение config.ini и переменных окружения, валидация настроек |
| `BotService.go` | Приём апдейтов, антифлуд, состояние чатов, отправка и затирание сообщений |
| `Handlers.go` | Вся логика бота: команды, кнопки, поиск и запоминание группы |
| `Keyboards.go` | Reply-клавиатуры и подписи кнопок |
| `Logger/` | Логи с уровнями DEBUG/INFO/WARN/ERROR, пишутся в консоль и в файл |
| `Schedule/` | Загрузка Google-таблицы, парсинг листов, форматирование |
| `Schedule/Index.go` | Хэш-индекс групп: поиск за O(1) вместо перебора |
| `Database/` | Хранение выбранной группы (GORM + SQLite) |

## Как устроено расписание

Пары длятся 90 минут, и в таблице записано только начало — конец бот считает сам
(`Schedule/Weekday.go`, `TimeRange`).

Таблица — шесть вкладок, по одной на курс. На каждой вкладке слева три колонки
(день недели, время, «в»/«н» — верхняя/нижняя неделя), а дальше вправо идут
блоки по 10 колонок на группу: дисциплина, здание, две аудитории, вид занятия,
кафедра, должность, преподаватель.

Номер группы и её имя лежат в первой строке блока. Встречаются три варианта
записи, и парсер понимает все:

* `8261160 (18.1-642)` — номер и имя
* `8241160` — только номер
* `18.1-512` — только имя, без номера

Ключом группы служит номер, а если его нет — имя. Именно ключ хранится в базе
как выбор пользователя.

Каждая вкладка скачивается как CSV по своему `gid` (`export?format=csv&gid=...`)
и складывается в кэш в памяти; фоново он обновляется раз в `RefreshMinutes` минут,
так что запросы пользователей никогда не ждут сеть. Если Google недоступен,
остаётся последний удачный снимок.

`gid` вкладок прописаны в `config.ini`. Обычная правка данных внутри вкладки их
не меняет — обновлять нужно, только если вкладки пересоздадут заново (тогда взять
`#gid=...` из адресной строки). При копировании таблицы на новый семестр `gid`
сохраняются, так что достаточно поменять один `SpreadsheetId`.

## Чистота чата

В чате постоянно живёт ровно одно закреплённое сообщение — приветствие с кнопкой
«Смена группы». Всё остальное считается временным: и ответы бота, и нажатия
пользователя. Перед каждым новым действием временные сообщения удаляются, так
что на экране остаётся закреплённое приветствие плюс последний ответ. Это
касается и режима «Вся неделя», который присылает семь сообщений сразу —
они стираются одним блоком.

Листание дней кнопками «<»/«>» не создаёт сообщений вообще: дата
зашита в callback кнопки, и бот переписывает ту же карточку на месте.

## Расписание физры (спецмед)

Ведётся вручную в отдельной Google-таблице, указанной в секции `[physed]`.
Структура листа:

```
День     | 8:00           | 9:40             | 11:50 | ...
пн - в   |                | Перепелкин В.В.  |       |
пн - н   |                | Перепелкин В.В.  |       |
вт - в   |                |                  | Нихорошкина А.В. |
```

Первая строка — время пар, дальше строки вида `<день> - <в|н>`, в ячейках
фамилия преподавателя. Разбор нестрогий: регистр, лишние пробелы и разные
виды тире допускаются, день можно писать полностью (`понедельник - в`).

Если в один слот обе недели ведёт один и тот же преподаватель, бот печатает
строку один раз без пометки недели — как это и читается на бумажном расписании.
Если преподаватели разные или занятие только на одной неделе, ставится `[в]`
или `[н]`. Дни без занятий не печатаются.

Место занятий одно на все пары, поэтому задаётся в конфиге (`Venue`), а не в
таблице. Пустой `SpreadsheetId` отключает раздел — кнопка тогда честно
сообщает, что расписание не подключено.

Вывод всегда текстовый, а не картинкой: связь в корпусах бывает плохой, и
текст доходит мгновенно.

## Поиск группы

При каждом обновлении расписания строится неизменяемый индекс (`Schedule/Index.go`)
из трёх хэш-таблиц: по ключу, по точному написанию (номер или имя) и по всем
подстрокам длиной от двух символов. Любой запрос пользователя — это одно
обращение к map, без перебора групп и без копирования списка.

## Устойчивость

Несколько вещей, которые важны при долгой работе:

* **Плохие данные не затирают хорошие.** Если таблицу закрыли или удалили,
  Google отвечает `200` с HTML-страницей входа. Бот проверяет `Content-Type` и
  отказывается принимать не-CSV, а если разбор дал ноль групп при непустом
  прошлом снимке — оставляет прежний и пишет `ERROR`. Без этого одна ошибка
  доступа обнулила бы расписание у всех.
* **Память не растёт бесконечно.** Состояние чата (блокировка, таймеры,
  список сообщений к затиранию) освобождается после двух часов тишины.
  Занятый чат при этом не трогается — уборщик проверяет блокировку.
* **Паника в обработчике не роняет бота** — каждый апдейт обёрнут в `recover`.
* **Сеть не блокирует ответы**: расписание отдаётся из снимка в памяти,
  запросы к Google идут только в фоне.

## Чётность недели

«Сегодня»/«Завтра»/«Текущая неделя» показывают только пары нужной недели:
нечётный ISO-номер недели → «в» (верхняя), чётный → «н» (нижняя).

Правило живёт в `Schedule/Weekday.go` (`ParityFor`). В Python-версии оно было
другим — отсчёт от жёстко прошитой даты `2025-09-01` — и давало противоположный
результат, так что если расписание сдвинется на неделю, менять нужно именно эту
функцию.
